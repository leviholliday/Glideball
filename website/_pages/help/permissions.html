What each one is for

PermissionWhat Glideball uses it for
AccessibilityChanging mouse button and scroll events on their way to your apps: turning a button into a shortcut, a combo or a click, and scrolling the page the way your scroll mode says. It also lets Glideball send the shortcut you picked for a button.
Input MonitoringReading your trackball directly, so Glideball knows which device a click or scroll came from and can read the scroll ring's ticks. That's how it changes only the trackball and leaves your trackpad and other mice alone.

Until both are on, your trackball works normally and Glideball does nothing.

What Glideball can and can't see

macOS names these permissions broadly, so they sound like more than they are. Here's exactly what Glideball looks at:

  • Mouse buttons: presses, releases and drags.
  • Scrolling: the scroll ring, and scroll events, so it can pass your trackpad's straight through.
  • Pointer movement from pointing devices: for the speed graphs on the Overview tab. Plain pointer moves only pass through Glideball while Drag lock is on.
  • Which modifier keys are held: Shift, Control, Option and Command (⇧⌃⌥⌘). For example, Command plus scroll keeps its normal meaning, like zooming.

It does not see what you type. It never listens to letter, number or other keys, only whether a modifier key is down. It only opens mice and other pointing devices, never your keyboard. The one keyboard shortcut it watches for, ⌃⌥⌘G to pause, is registered with macOS the normal way and needs no permission at all.

None of this leaves your Mac. The one exception is a scroll log (scroll and button timings, no keystrokes), and only if you leave it attached to a feedback report you send. The daily totals on the Overview tab stay on your Mac. The code that does all this is in Engine.swift if you want to check.

How to turn them on

  1. Click the buttons in Glideball's window

    Allow Accessibility… and Allow Input Monitoring… each open the right page of System Settings.

  2. Switch Glideball on in each list

    In System Settings › Privacy & Security › Accessibility, and then Input Monitoring. macOS may ask for your password.

  3. Come back to Glideball

    The checkmarks update by themselves.

They're on, but nothing changes

Remove Glideball from both lists with the minus button, add it back, and restart Glideball. Or reset both at once in Terminal, then restart Glideball and allow them again:

tccutil reset All com.leviholliday.glide

Updates keep your permissions, because macOS ties them to Glideball's signature and every update is signed the same way.
